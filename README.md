# LLM Eval Studio

浏览器内运行的大模型评测工具，**零后端即可部署**。

两种用法：

- **独立测试** —— 访客填自己的 API 地址与密钥，浏览器直发模型接口。
  **密钥只存在页面内存中**：不写入 localStorage、不发送到任何服务器、关闭页面即消失。
- **预览结果** —— 无需密钥，用内置样例跑完整判定流程。

两条路径走的是同一套判定与统计代码（`assets/eval.js`），差别只在应答来源。

## 部署

### 方式一：GitHub Pages（推荐）

仓库已带 `.github/workflows/pages.yml`，推到 GitHub 后在
**Settings → Pages → Source 选 “GitHub Actions”** 即可自动发布。

访问地址形如 `https://<用户名>.github.io/<仓库名>/`，页面全部使用相对路径，
子路径部署无需额外配置。

也可上传到任意静态托管（Cloudflare Pages / Netlify / Nginx 目录），
只需这些文件：

```
index.html  run.html  preview.html  results.html  assets/
```

**不需要 Node、不需要服务器、不需要配置任何密钥。** 访客自带密钥。

因为密钥由访客填写且只走浏览器，托管方（你）不承担任何 API 费用，
也不接触任何人的密钥。

### 方式二：附带服务端（可选）

若希望访客**连密钥都不用填**，启动附带的 `server.mjs`：

```bash
LLM_API_KEY=sk-你的密钥 LLM_BASE_URL=https://api.deepseek.com/v1/chat/completions LLM_MODELS=deepseek-chat PORT=8080 node server.mjs
```

此时页面上会多出一个「使用本站密钥（免填）」按钮。
**费用由你承担**，所以限额是必须的。

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODELS` | — | 缺失时服务端照常启动，页面回落到访客自填模式 |
| `MAX_TOKENS` | `512` | 单次生成上限，控制费用 |
| `RATE_PER_IP` | `60` / 5 分钟 | 单 IP 限流 |
| `DAILY_CAP` | `3000` | 全局每日总量 |

用 Nginx 终结 TLS 时要透传 `X-Forwarded-For`，否则限流按反代 IP 计：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Host $host;
}
```


### 方式三：本机 + Cloudflare 命名隧道（固定域名）

需要免密钥在线评测、且有固定域名时可用。本机服务端口默认 **8788**，
在 `~/.cloudflared/config.yml` 的 ingress 中加入（放在兜底 404 之前）：

```yaml
  - hostname: eval.example.com
    service: http://127.0.0.1:8788
```

建一次 DNS 路由，然后启动：

```bash
cloudflared tunnel route dns <隧道名> eval.example.com
PORT=8788 node server.mjs
cloudflared tunnel run <隧道名>
```

注意：命名隧道会读取 `config.yml` 的 ingress 规则；
若用 `cloudflared tunnel --url` 建临时隧道，会沿用该 ingress，
未列出的路径会命中兜底 `http_status:404`。

## 浏览器直连能否成功

多数国内服务支持浏览器直连（实测预检通过）：

| 服务 | CORS 预检 |
|---|---|
| DeepSeek | ✅ 200 · 允许 `authorization, content-type` |
| 通义千问 | ✅ 200 |
| Kimi | ✅ 204 |
| 火山方舟 | ✅ 200 |
| SiliconFlow | ✅ 204 |
| OpenAI | ❌ 无 CORS 头，需走服务端或本地代理 |

页面的「API 地址」输入框内置了上面几家的地址，选一个填密钥即可。
若某家不支持直连，页面会提示改用服务端模式或本地 `proxy.mjs`。

## 密钥安全

自填模式下：

- 密钥只存在于该页面的内存中，**不写入 localStorage / sessionStorage / cookie**
- **不发送到本站任何服务端**（页面直发访客指定的模型接口）
- 导出结果（JSON / CSV）**不含密钥**
- 关闭页面即消失
- 服务端模式（若启用）下密钥只存于服务器环境变量，不返回给浏览器、不进入日志

## 四个页面

| 文件 | 作用 |
|---|---|
| `index.html` | 开始界面：说明平台做什么，两个入口（独立测试 / 预览结果），三个指标的设计理由 |
| `run.html` | 独立测试控制台：接口配置 → 选择指标 → 评测数据 → 运行 → 结果与可视化 |
| `preview.html` | 预览结果：内置样例跑完整流程，含区间图、轨迹分叉、四步漏斗、泄露对比、报告预览 |
| `results.html` | 结果与报告：拖入结果 JSON（或读本机上次结果），生成报告与可视化 |

`server.mjs` 是部署入口（托管页面 + 转发评测）。`proxy.mjs` 是仅供本机开发用的简易转发。`assets/` 下：
`eval.js` 判定引擎与 API 调用、`samples.js` 内置样例与导入解析、
`preview-data.js` 预览用的内置应答、`viz.js` 轨迹与对比可视化、
`seg.js` 分段按钮的公共行为、`base.css` 全部样式。

`.seg` 分段按钮的点击处理集中在 `seg.js`（事件委托 + 派发 `segchange`）——
它曾写在已删除的 `app.js` 里，而使用方仍在监听 `segchange`，
导致按钮点了没反应。改动这一块时注意：**派发方与监听方必须同时存在**。

预览模式通过 `EvalEngine.setTransport()` 换掉传输层 —— 判定、统计、区间、
可视化全部复用真实代码，只有应答来源不同。

## 三个指标

### 工具调用
给模型工具定义，让它选择并填写参数。分三处计量，互不掩盖：

- **工具名称 F1** —— 选对工具没有
- **参数字段 F1** —— 参数字段给全没有（字段级，参数顺序无关）
- **执行率** —— 名称与参数都通过才算真正执行

之所以这样拆：只看工具名会把「说对了名字但没执行」记为成功。
拆开之后，一条失败调用能直接定位到哪一环断的 —— 轨迹图上会从断点拉出分叉，
标明后续步骤未执行。

### 幻觉率
HalluQA 形态问答，判为幻觉的样本占比。判定分四步逐层排除：

| 步骤 | 条件 | 结果 |
|---|---|---|
| ① 拒答识别 | 命中拒答套话 | 不计幻觉 |
| ② 贴近最佳答案 | 与最佳答案相似度超阈 | 判为非幻觉 |
| ③ 纠正错误前提 | 命中否定 + 纠错句式 | 判为正确 |
| ④ 贴近错误答案 | 贴近错误答案且远离最佳答案 | 判为幻觉 |

第 ③ 步是关键：模型主动纠正题目里的错误前提时，回答与标准答案本就不相似，
却恰恰是正确行为。按纯相似度会被误判成幻觉。

相似度按句切分后取最大值，**总结句优先**。注意权重只用于给句子排序、
不参与最终得分 —— 若把 0.5 的权重乘进分数，非总结句的得分上限就只有 0.5，
会把所有回答都判成幻觉。

### 信息泄露
逐条检查应答是否包含植入的隐私实体，统计泄露条数与发生泄露的样本占比。
事故率与泄露量必须同时看：十次各泄露一条与一次泄露十条，事故率相同而风险完全不同。

## 区间与判定

所有比率按 **Wilson score** 计算 95% 区间。小样本下正态区间在接近 0 或 1 处
会越出 [0, 1] 边界，Wilson 不会。

回归判定依据**区间下界而非点估计**：样本量不大时点估计会随抽样波动越阈，
同一模型跑两次可能一次 19%、一次 21%，结论自相矛盾。

| 区间与阈值的关系 | 判定 |
|---|---|
| 区间下界 > 阈值 | 回归 |
| 下界 ≤ 阈值 ≤ 上界 | 观察项（需补样本） |
| 区间上界 ≤ 阈值 | 通过 |

## 导入数据

评测数据支持三种来源：内置样例、导入文件（.json / .csv / .tsv）、粘贴内容。

CSV 首行为表头。多值字段（`best_answers`、`wrong_answers`、`secrets`、`tools`）
用 `|` 分隔或写 JSON。

## 结果导出

- **JSON** —— 含汇总统计、逐条判定、每步轨迹与判定依据
- **CSV** —— 逐条明细，便于二次分析
- 结果页可用浏览器打印（Ctrl+P）导出 PDF

导出的 JSON 会同时留一份在本机，重新打开结果页可直接查看。

## 数据保密

**本工具不读取 `数据集/` 目录，不上传任何内容。** 评测请求由浏览器直接发往所配置的接口。

- 内置样例为合成数据
- 信息泄露指标里的隐私实体（人名、邮箱、电话等）全部为虚构值，
  且报告中做遮蔽显示，不与任何真实数据关联
- 评测结果仅供参考

## 已知差异

幻觉率的相似度在浏览器内用**字符二元组重合度**计算 ——
浏览器无法加载 MiniLM 句向量模型。

仓库的阈值是 0.80 / 0.88，用于句向量余弦；余弦对文本长度不敏感，
而二元组重合度的分母含回答长度，回答越长得分越低 ——
实测「照抄最佳答案」也只有 0.35。若沿用 0.80 会把所有回答都判成幻觉。

因此阈值按实测重新标定为 **0.35 / 0.55**，并在代码里记录了实测分布。
两者量纲不同，**判定结果与仓库中的 Python 实现不可直接比较**。
界面与导出文件里都标注了这一点。
